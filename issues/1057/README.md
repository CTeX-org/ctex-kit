# Issue #1057 资产

`xeCJKfntef` 的装饰命令嵌套使用时，被嵌套的那一段有时无法断行。

结论是这属于 `ulem` 的固有约束，不是回归缺陷，因此处置方式是补文档加补回归测试，
不改实现。

## 两类命令

按装饰的绘制方式分两类，嵌套时的断行能力不同：

- **线型命令**：`\CJKunderline`、`\CJKunderdblline`、`\CJKunderwave`、`\CJKsout`、
  `\CJKxout`、`\CJKunderanyline`。它们借 `ulem` 扫描正文并沿基线画出连续的线条。
- **符号型命令**：`\CJKunderdot`、`\CJKunderanysymbol`。它们逐字放置独立的点或
  符号，不需要 `ulem` 的扫描过程。

六个命令单独使用都能正常断行。**两个线型命令相互嵌套时，被嵌套的那一段无法断行**；
嵌套的先后顺序不影响这一结果，原生的 `\uline` 与本宏包的线型命令相互嵌套时同样如此。
任一层为符号型时断行正常。

## 根因

`ulem` 只允许最外层的线型命令启动扫描。内层线型命令走 `\UL@onin` 复用外层已经打开的
扫描过程，它的正文被整段放进一个刚性 `\hbox`（实测 107.22pt，盒子内部没有
discretionary），盒子内部不再留有断点，于是 TeX 只能让这一段溢出到页面右边。

发布版 v3.10.4（系统 TeX Live）与工作树 v3.10.5 的行为完全一致，同一个 10cm 页宽的
MWE 在两版下溢出量同为 276.99pt。这是「长期约束而非某个版本的回归」的证据。

## 处置

见 PR #1054。手册改动三处：新增 §3.6.1 说明分类、根因与三条替代写法；
`\CJKunderdot` 处补一句「嵌套后仍然可以正常断行」并指向新小节；「已知问题和兼容性」
那份「间距行为正确」的命令清单处声明**本节只讨论 CJK 间距、不涉及断行**并交叉引用
新小节 —— issue 作者正是把那份间距清单外推成了断行保证，这是报告产生的直接成因。

## 判据选择

新增回归 `fntef-nest-linebreak01` 同时给 `\UL@onin` 补上了第一份回归保护。此前
`llmdoc/reference/build-and-test.md` 明确记载该路径无法回归保护，理由是 `\UL@onin` 用
`\setbox\UL@box\hbox{{#1}}` 把正文整体装进盒子，「收缩量丢失」这个症状在那里恒定不
显现（实测在该分支重新引入缺陷乃至整段删掉，全套测试都保持全绿）。

本次换用**能否断行**作为可观察量：同一句 `\setbox\UL@box\hbox{{#1}}` 对收缩量不可见，
对断点却是决定性的。用计数器插桩确认分派确实不同——线型套线型时 `\UL@onin` 计数为 1，
线型套符号型时为 0。

基线是双向的：含 `Overfull` 的两项是限制存在的证据，不含 `Overfull` 的四项校验
「符号型可以自由嵌套」这句文档结论。变异验证针对后一侧：把其中一项内层的
`\CJKunderdot` 换成线型 `\CJKunderwave`，基线因多出 `Overfull` 行而失败。
