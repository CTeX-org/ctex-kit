# Issue #1067 资产

`\CJKunderline` 正文里用花括号括住一段内容时，该处中西文间距（`\CJKecglue`）的**可收缩量**
失效。自然宽度不变，因此只在需要压缩的场合显现。**已在 v3.10.6 修复。**

## 成因

不在 `ulem` 的切词 —— 实测两种写法切出的词相同，只差一对花括号
（`WORD=[\prg_do_nothing: hello]` 对 `WORD=[\prg_do_nothing: {hello}]`）。

花括号是在词内容交给 `\UL@start` **之后**、在片段盒**内部**才展开成分组的，于是边界检测在
盒内、且在用户分组内触发；`\@@_ulem_glue:n` 的 group tag 守卫比对保存的 `T1L4` 与当前的
`T1L5` 不相等，走 else 分支，间距连收缩量一起固化在定宽片段盒内。

修法是把一处间距拆成两半输出：盒内放不可伸缩的 `kern` 占住自然宽度（排版位置与盒宽都不变），
伸缩量记进全局 skip，到词尾搬运处（已在片段盒外、用户分组外）再补一个零宽而带伸缩的 glue。
守卫本身未改动 —— 绕过它并不能解决问题（强制搬运后 glue 落进 `\cleaders` 内部、仍在盒内），
还会让分组内的字体设置丢失。

## 文件

- `issue1067-measure.tex` — 测量脚本。在两个版本上分别跑它，各写法压窄 2pt 时的 `\badness`
  会打进 log（格式 `R|<名称>|<自然宽>|<badness>`）。
- `issue1067-table.tex` / `issue1067-before-after.png` — 修复前后对比表。**表里的数值由上面
  那个脚本分别在两个版本上实测得出、再静态排版**，不是现场测量。

  这样分离是有原因的：把测量与排版混在同一个文件里时，寄存器复用与「用宏承载正文」两次给出
  了错误读数。后者尤其隐蔽 —— `xeCJK/testfiles/fntef-shrink01.lvt` 开头早已警告过，正文经宏
  间接展开时收缩量同样进不了外层（#1026 的既有限制），于是两种写法一起退化、差异被抹平。
  测量脚本里的正文因此全部字面书写。

## 实测数据

压窄 2pt 时的 `\badness`（有限值 = 收缩量够用，`1000000` = 不够）。两侧都用对应版本现场
`l3build unpack` 出的 `.sty`，引擎 XeTeX，TeX Live 2026，11pt 字号：

| 正文写法 | 自然宽 | 修复前 | 修复后 |
| --- | --- | --- | --- |
| `虚室 {hello} 生白`（无装饰命令，oracle） | 73.61pt | 55 | 55 |
| `\CJKunderline{虚室 hello 生白}` | 73.61pt | 55 | 55 |
| `\CJKunderline{虚室 {hello} 生白}` | 73.61pt | **1000000** | **55** |
| `\CJKunderline{虚室 \textbf{hello} 生白}` | 77.14pt | **1000000** | **55** |
| `\CJKunderline{虚室 {{hello}} 生白}` | 73.61pt | **1000000** | **55** |

三种带编组的写法都从「压不进」变为与 oracle 一致，**自然宽度全部不变**。

## 为什么没有「一眼可见」的截图

这个缺陷的绝对量就是一个 `\CJKecglue` 的收缩分量（11pt 字号约 1.2pt）。用
`\fbox{\hbox to <宽度>{...}}` 构造时，修复前的溢出量实测只有 **0.676pt** —— 12pt 字号在
170dpi 下不到 2 像素，图上看不出来。段落排版下更是两版都不溢出，因为断行可用的伸缩量远多于
固定宽度的盒子。

先前的一版资产里放过一张这样的图并标注「溢出框外」，图其实不支持那个说法，已删除。差异过小
时用数值呈现更诚实。

## 不属于本问题的情形

`\CJKunderline{虚室 {文字} 生白}`（纯汉字加编组）的 badness 在修复前后都是 1000000，但那
**不是**本缺陷：它的 oracle 本身就是 1000000 —— 纯汉字之间只有 `\CJKglue`（`0pt plus 0.96`，
只有伸长、没有收缩），本来就没有可收缩的间距。先前一版资产把它列为「受影响」并说「比原报告
更广」，那是错的，实测 oracle 后否证。

判断某种写法是否受影响，必须先测它自己的 oracle。
