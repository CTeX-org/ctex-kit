# [Task Reflection]

## Task

- 解决 Issue #1012：`\CJKunderwave` 和 `\CJKxout` 在普通正文、相邻带 `-`
  的命令、标点、换行及伸缩 `CJKglue` 中出现局部过密、断开或左右不均。
- 保留修复前已经正确的装饰总长度、相对正文的居中方式，以及普通形式和带 `-`
  形式各自的端点语义。
- 让默认波浪线和斜删除线的周期随字号缩放，并让正文片段、中文字间距与命令端点
  各自采用符合其几何作用的处理方式。
- 保留 `underwave/symbol` 自定义入口原有的 `\xleaders` 行为，不把默认图案的专用
  算法错误地套到任意用户符号上。

## Expected vs Actual

- 最初预期：问题来自 `ulem` 在每个正文片段两端加入的 `\UL@pixel` 重叠；把
  `\UL@pixel` 清零，再为带 `-` 的形式手工补回命令首尾空白，应能消除波浪双峰和
  斜线聚集。
- 实际：这项改动虽然减少了局部重画，却同时改掉了 `ulem` 已有的装饰区间。波浪线
  和斜删除线相对正文缩短并偏移；相邻的 `\CJKunderwave-`、`\CJKxout-` 又出现
  过大的断口或左右不对称。用户在“文心雕龍”“養氣”等手册原文中很容易看到这些
  退化。
- 第二个预期：恢复 `ulem` 的几何，只把默认图案换成随字号缩放的 `1em/3`
  `l3draw` 单元，并让波浪继续使用 `\xleaders`、斜线继续使用 `\cleaders`，就能
  同时解决密度和接缝问题。
- 实际：缩放图案解决了固定字号和数学字体带来的密度漂移，却没有解决“每个正文片段
  都重新分配余量”这一根本问题。`\xleaders` 的起始相位还会随可用宽度改变；伸缩
  `CJKglue`、外层水平偏移和命令端点因此仍会暴露断口或重叠。
- 第三个预期：把默认波浪和斜线统一改成宽 `1em/4` 的普通 `\leaders`，让同一水平
  列表共享相位，应能消除所有接点差异。
- 实际：统一相位仍不能表达三种不同的几何。正文需要完整、等距的周期；实际伸缩的
  `CJKglue` 不应挤入或丢掉一个周期；普通形式和带 `-` 形式还需要不同的外端点。
  只更换 leaders 类型，无法同时把这三项约束说清楚并固定下来。

## What Went Wrong

1. **把 `\UL@pixel` 当成可以单独删除的缺陷。** 它不仅用于盖住直线接缝，也参与
   `ulem` 对每段 leaders 的长度计算及带 `-` 形式的首尾缩减。第一版只看到了重复
   绘制，没有先保护已经正确的装饰长度和居中这两个不变量。

2. **手工补空白不等价于恢复原有几何。** 清零 `\UL@pixel` 后，第一版在第一个和
   最后一个片段外侧插入普通空白，并对窄片段另做限制。空白不会绘制装饰，也不能
   恢复原 leaders 区间的相位和余量分配；对相邻的带 `-` 命令，这种差异会在两个
   命令的接点累积，形成明显断口和左右留白不均。

3. **把“片段是否重叠”误当成唯一自变量。** 波浪线和斜线都是有方向的重复图案。
   单元宽度、正文片段宽度、外层水平位置和伸缩胶水的实际宽度都会改变可见接点。
   取消重叠、缩短周期或统一相位只能各解决其中一部分，不能代替对不同接点逐类定义
   行为。

4. **过早把中间方案写成稳定合同。** 提交
   `67388c2290c068085794223f0cb4fcc76a4d0dea` 的 `1em/3 + \xleaders/\cleaders`
   方案改善了缩放，却随后被继续实验推翻。稳定 `llmdoc` 当时仍把它写成当前决定，
   甚至要求维护者“保留未经改写的 `ulem` 几何”。固定提交上的独立盲审因此给出
   `REQUEST_CHANGES`：实现和测试没有发现问题，但 architecture、reference、decision、
   reflection、lessons 和 index 共同描述了已经被替换的合同。这说明文档更新不能只在
   第一次看似可行时进行；实现继续演进后，必须重新核对每条稳定结论。

5. **一次实验加载了错误的宏包文件。** 当时直接编译临时 MWE，日志实际解析到
   `/home/liam/texlive/2026/texmf-dist/tex/xelatex/xecjk/xeCJKfntef.sty`，而不是工作树
   生成的 `xeCJK/build/unpacked/xeCJKfntef.sty`。因此图上标为“修复后”的结果仍来自
   TeX Live 旧版，实验标签与实际代码不一致。之后的正式证据都通过编译日志核对了
   宏包路径。

6. **历史视觉样例不足以保护普通正文。** #531/#967 主要用大字号、重黑体和规则的
   “国国国”观察相位。重黑字形会降低细小波浪和斜线异常的醒目程度，整齐的全角宽度
   又容易偶然整除固定装饰单元；这些截图不能代表手册的 10.53937pt 宋体、标点、
   相邻带 `-` 命令和实际伸缩胶水。

## Root Cause

旧实现同时使用了两套互不成比例的尺度：`ulem` 按正文片段、字符间距和断行结果决定
装饰区间，默认波浪符号却来自固定的 6pt `lasy` 字体，宽度约为 5pt；斜删除线由数学
字体中的 `/` 构成，宽度随数学字体和离散字号变化。每个片段重新运行 `\xleaders` 或
`\cleaders` 时，不能整除装饰单元的余量会重新分配。于是相邻片段即使总宽度正确，
波形或斜线在接点处仍可能显得过密、断开或偏向一侧。

更深一层的问题是，正文片段、`CJKglue` 和命令外端点并不是同一种区间：

- 正文片段需要完整、连续并相对自身稳定的周期；外层水平偏移不应改变第一单元的位置。
- `CJKglue` 的实际宽度可能因断行伸缩，而且通常不是周期宽度的整数倍。在这里继续
  排列周期盒子，会让短胶水多出或少掉一个装饰单元。
- 普通形式的装饰应在正文左右对称外伸；带 `-` 形式则应恰好停在正文边界。把两种形式
  交给同一段余量分配，容易同时损伤总长度和接点。

因此，`\UL@pixel` 既不能简单清零，也不能原样保留后继续让同一 leaders 算法处理所有
区间。当前固定实现 `7df9ae72e9460f4d3b2f2e558a9822ce6ac4bfbc` 采用以下分工：

- `\@@_fntef_wave_symbol:` 和 `\@@_fntef_xout_symbol:` 都用 `l3draw` 绘制宽
  `1em/4` 的图案。波浪振幅、斜线高度和线宽也相对 `em` 计算；常规全角字符每字约
  容纳四个单元，斜删除线不再依赖数学字体。
- 两个默认图案都使用 `\cleaders` 排列正文片段，使图案相对片段居中，并且不随外层
  `0pt/1pt/3pt/5pt` 水平偏移改变相位。
- 周期路径把 `\UL@pixel` 减半，使整数周期的正文片段实际落在正文边界；普通形式再在
  左右各画半个单元，保留原来的总长度和对称居中。带 `-` 形式不画这两个外端点，图案
  恰好落在正文边界。两种形式不改变命令自身宽度。
- `\@@_ulem_ccglue:` 对 `CJKglue` 进入专用分支，不在胶水中再排列周期盒子。波浪的
  单元从波峰开始并在波峰结束，胶水区用同线宽水平线连接两侧波峰；斜删除线在胶水区
  只保留实际空白，让相邻斜线的节距增加该胶水宽度。
- 这项专用处理只适用于中文字间距。正文中的 `\quad` 和一般显式 `\hskip` 仍由
  `ulem` 原路径绘制装饰；标点和 `CJKecglue` 也不经过这个专用分支。
- `underwave/symbol` 只有在值仍是默认 `\@@_fntef_wave_symbol:` 时才进入上述周期路径。
  用户自定义波浪符号继续使用历史 `\xleaders` 行为，其宽度、相位和视觉结果仍由用户
  负责检查。

## Rejected Designs and Lessons

### 清零重叠并手工补端点

提交 `33579b340b5bf2bb91799134165ef905e41dda40` 曾清零 `\UL@pixel`，再用普通空白
补带 `-` 形式的首尾。它确实减少了局部重复绘制，但破坏了装饰总长度、居中和相邻命令
接点，已经被否决。教训是：观察到某个内部量参与错误，不等于可以删除它；先列出并
量化现有正确行为，再决定调整点。

### `1em/3` 图案加原 leaders 选择

提交 `67388c2290c068085794223f0cb4fcc76a4d0dea` 恢复了 `ulem` 原路径，并把波浪和
斜线改为宽 `1em/3` 的 `l3draw` 图案；波浪继续用 `\xleaders`，斜线继续用
`\cleaders`。它正确识别了“图案尺度应随字号变化”，却没有处理外层偏移、伸缩胶水
和端点之间的不同要求，已经被否决。教训是：减小周期能降低误差的醒目程度，却不能
证明接点几何正确。

### `1em/4` 图案加普通 `\leaders`

提交 `bd3edb54cc85259619802b6f6aed645109186ad4` 又尝试让两个默认图案都使用普通
`\leaders`，希望整条水平列表共享相位。这个方向提醒了我们必须检查外层水平偏移，
但它仍把正文、胶水和命令端点交给同一种余量分配，无法分别表达三者的合同，随后被
当前实现替换。教训是：相位一致只是接缝正确的一项条件；装饰区间和端点语义同样需要
独立验证。

## What Worked

### 1. 真实绘图度量

`fntef-underline-offset` 直接构造真正的 `l3draw` 波浪和斜线盒子，固定它们在 8pt、
10.53937pt 和 15pt 下的宽、高、深。当前宽度分别为 2pt、2.63484pt 和 3.75pt，
与 `1em/4` 一致；高度也随字号变化。这一层证明默认装饰单元确实按当前字号缩放，
而不是只在测试替身中满足尺寸约定。

### 2. 轻量规则盒子节点替身

真实 `l3draw` 路径会在 `.tlg` 中展开大量 PDF 绘图 special，使普通节点基线增加数千
行，却没有为装饰区间和断行判断增加信息。节点测试因此在完成真实绘图度量后，把波浪、
斜线和半单元端点临时换成同尺寸规则盒子，再检查 leaders 类型、节点次序、命令宽度和
断行行为。

这层覆盖普通形式、带 `-` 形式、相邻命令、连续 CJK、标点、多个字号、换行和实际
伸缩的 `CJKglue`。它还确认默认波浪和斜线选择 `\cleaders`，自定义
`underwave/symbol` 保持 `\xleaders`，重复使用保存的装饰盒子不会改变宽度。规则
盒子替身只能固定结构，不能证明波浪曲线或斜线本身画得正确，仍须与真实绘图和视觉
证据合用。

### 3. `fntef-phase01` PDF 坐标检查

普通 `.tlg` 节点日志不能证明 PDF 页面上的周期盒子实际落在哪里。`build.lua` 因此为
`fntef-phase01` 增加专用后处理：先用 `xdvipdfmx -z 0` 生成不压缩内容流的 PDF，再由
`testfiles/support/fntef-phase-check.lua` 读取标记和图案盒子的实际横坐标。测试固定了：

- 波浪和斜线在外层偏移 `0pt/1pt/3pt/5pt` 时相位不变；
- 普通形式左右各对称外伸半个单元，带 `-` 形式恰好落在正文边界，且两种形式命令
  宽度相同；
- 固定和实际伸缩的 `CJKglue` 都不新增周期盒子，胶水两侧的节距等于“一个周期加
  实际胶水宽度”；
- 相邻带 `-` 命令保持一个周期的节距；
- 普通 `\quad` 仍被绘制装饰，没有被 `CJKglue` 专用分支误处理。

Lua 检查把五项 PASS 写回 `.log`，再由 `.tlg` 固定结果。负向实验曾让这项检查以
“正文图案盒之间出现断口”失败，说明它不是只验证夹具能够运行，而是确实能拦住旧
接点算法。

### 4. 精确视觉 MWE 与字体矩阵

从 xeCJK 手册提取的一页 MWE 保留 Noto Serif CJK SC Regular、TeX Gyre Pagella、
10.53937pt 正文字号及原示例文字，覆盖“虚室生白，吉祥止止”、相邻的
“文心雕龍”“養氣”和窄行换行。补充矩阵覆盖 Noto Serif CJK SC Regular 的 8pt、
10.53937pt、15pt，Noto Sans CJK SC Regular／Black，以及 8.5em 行宽下实际伸缩的
`CJKglue`。这些图像用于检查曲线、接点和视觉密度，不能由节点日志或坐标检查代替。
正式产物的日志必须明确加载工作树生成的 `xeCJKfntef.sty`。

### 5. 全量回归与 PDF 文本语义

固定提交上的正式盲审重新运行六项 fntef 相关测试，`fntef-phase01` 的 Lua 后处理实际
执行并输出五项 PASS；随后 xeCJK 全量回归为 113／113，通过 `l3build doc` 生成
244 页 `xeCJK.pdf` 和 51 页 `xunicode-symbols.pdf`。

同一盲审还分别编译普通 PDF 与开启 `\DocumentMetadata{tagging=on}` 的最小样例，
覆盖默认波浪、默认斜删除线、自定义 `underwave/symbol` 和
`\CJKunderanysymbol`。两类 PDF 用 `pdftotext -raw` 和 `-layout` 提取时都只包含正文，
没有装饰字符。这说明 #1012 的几何修改没有破坏 #1017 已建立的空 `ActualText` 与最小
范围 tagging 暂停合同。

## Font, Weight, Size, and Glue Findings

- 对常见的全角 CJK 字体，在同一字号下更换 Noto Serif、Noto Sans 或字重，通常不
  改变字符的一 em 宽度和装饰几何；字体和字重主要改变异常是否醒目。宋体或常规字重
  更容易看出细小接缝，重黑体的正文笔画则可能掩盖它们。
- 字体不能被绝对排除：若字形前进宽度不是一 em，或内容包含西文、标点和特殊盒子，
  正文片段宽度仍会变化。这里的结论只针对本次矩阵中的常见全角汉字字体。
- 字号和“正文片段宽度／装饰周期宽度”的比例会直接改变几何。旧波浪固定约 5pt，
  所以 8pt、10.53937pt 和 15pt 得到不同余数；当前默认值把周期固定为 `1em/4`，使
  普通全角字符在这些字号下都约含四个完整周期。
- 伸缩 `CJKglue` 的实际宽度由断行决定，不要求它能被周期整除。当前实现把它从周期
  排列中分离：波浪用水平波峰连接表达这段距离，斜线则直接增加相邻单元的间距。
- `\CJKxout` 改用 `l3draw` 后，默认斜线不再受数学字体影响。TeX Gyre Pagella Math
  仍保留在精确 MWE 中，是为了完整复现手册环境及便于与旧输出比较。

## Missing Docs or Signals

- 既有说明把 `ulem` 的片段重叠直接写成应当取消的缺陷，没有先记录装饰总长度、居中
  和两种端点形式是必须保护的不变量。这使第一个中间方案过早变成了架构结论。
- 后续文档又把 `1em/3 + \xleaders/\cleaders` 写成当前合同，没有在实现改为
  `1em/4 + 默认 \cleaders + 接点分离` 后重新核对。独立盲审能发现这一问题，说明
  固定提交审查不仅要看代码，也要把稳定知识当作可合并合同检查。
- 可视实验缺少“实际加载文件”这一基本信号。凡从源码树验证生成宏包，都应在日志中
  核对 `xeCJKfntef.sty` 的解析路径；文件名相同不能证明加载的是当前工作树版本。
- 节点测试若直接记录完整 PDF 绘图路径，会产生大量脆弱基线；若只用规则盒子，又会
  漏掉真实坐标和图形尺寸。需要明确保留“真实绘图度量＋同尺寸节点替身＋PDF 坐标
  检查＋精确视觉 MWE”四层分工。
- “与字体有关”必须拆开说明。常见全角字体和字重主要影响醒目程度；字号、字宽、
  装饰周期和实际胶水宽度才直接进入几何计算。
