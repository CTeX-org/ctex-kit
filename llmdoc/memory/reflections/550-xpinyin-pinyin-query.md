# 反思：#550 拼音查询命令

## Task

#550 是 2020 年的 wishlist：希望把「查拼音」从「排注音」里拆出来，提供返回拼音、首字母、声母、韵母的四个命令，并能选择声调形式。真实动机在评论里：用 `glossaries` 加 `bib2gls` 做中文索引时，CLDR 默认把中英文混排，想按拼音首字母分组就得手工给每个索引项加前缀。

issue 里有 stone-zeng 五年前给的原型。本轮先做调研（结论发在 issue 评论里），与用户逐条确认九个设计决策，然后实现：新增四个命令、两个选项（`tone`、`scheme`）、包选项 `query`，并新增 `pinyin-query01.lvt`。

## Expected vs Actual

- 预期：数据库已有拼音，四个命令只是取值加字符串处理，主要工作量在声母韵母的切分规则。
- 实际：切分规则确实需要设计，但**真正的约束是可展开性**，它决定了整个实现形状——数据要预生成，不能运行时算。另外调研阶段对数据形式的假设错了一处，全量校验时才发现。

## What Went Wrong

### 1. 误以为 Unihan 的拼音是分解形式

调研时我用 Python 的 `unicodedata.normalize('NFD', ...)` 显式分解过拼音，据此写了按码位遍历、遇到组合符就取声调的 Lua 代码。实跑后发现输出与输入完全一样：`zhōng` 只有 5 个码位，`ō` 是单独的 U+014D，**数据本身是预组合形式**。是我把「自己调用 NFD 之后的样子」当成了「数据原本的样子」。

`texlua` 没有 Unicode 正规化函数，所以改用显式对照表，列出该数据库实际用到的 29 个带附加符号的字符。

教训：验证数据形式要直接看原始字节或码位数，不要经过任何正规化步骤。我那次 Python 统计的每一行都调了 `normalize`，于是这个差异被自己的工具抹掉了。

### 2. 抽样校验漏掉了唯一的例外

改成对照表后，我先抽查了「中女绿安行么」六个字，全对。但对照表是按整字符查的，而全量校验（50325 条、57493 个读音）发现一个例外：「呣」的读音 `m̀` 是**裸的 `m` 加 U+0300**——Unicode 有 `ḿ`（U+1E3F），却没有 `m` 加钝音符的预组合形式。这一个字用抽样永远查不到。

修法是在对照表之外单独认出裸组合符。修好后全量零不符。

教训：表驱动的转换要用全量数据逐条比对，抽样只能证明主路径通。这类「Unicode 里恰好没有某个预组合写法」的例外，正是抽样的盲区。

### 3. 声调一律接在切出来的片段后面

早期实现里，声母和韵母都走同一条「片段加声调数字再标调」的路。结果「中」的声母排成了 `zh1`：`\@@_pinyin:n` 在片段里找不到可以标调的元音，就把数字原样输出了。

声母只由辅音组成，标不了调，所以它**永远**不带声调，四种 `tone` 取值下都一样。这一条是排出来才注意到的，不是设计时想到的。

### 4. 把 scheme 的判断提到了外层

`official` 模式的韵母不标调（原因见下），我一开始把这个判断放在「取哪一部分」的分支之外。结果 `\xpinyinvalue` 在 `official` 下返回 `uang` 而不是 `wáng`——它返回的是完整读音，与声母韵母怎么切分无关，不该受 `scheme` 影响。

判断必须放在「取韵母」这一支内部。这是个只影响一个命令的错，但如果没有逐命令列表核对，很容易漏过去：`\xpinyinvalue` 在 `literal` 下是正确的，只在 `official` 下才错。

### 5. 星号形式的去重把结果变成了空

星号形式要去掉重复项（「行」的四个读音里三个首字母都是 `h`）。我用 `\clist_put_right:Nx` 收集加工结果，`tone=mark` 时每一项都变成了空，输出 `,,,,`。

原因是 `tone=mark` 的输出含 `\@@_pinyin:n`，它是 `protected` 的，`x` 类展开留不下文本。更根本的是这个命令**把内容排版出来而不是返回字符串**（它经 `\l_@@_item_tl` 等变量逐段拼装输出），所以无论用 `x` 还是 `e` 展开都取不到文本。

最终做法是分两支：结果为纯文本时去重，`tone=mark` 时逐项输出不去重。首字母不受 `tone` 影响，总是纯文本，所以「行」能正确合成 `h,x`。

### 6. `unpacksuppfiles` 漏项，生成的 `.def` 只有版权头

查询表要单独成文件，于是 `xpinyin.lua` 多输出一个 `xpinyin-query.db`，`.ins` 里多一个 `\file{xpinyin-query.def}`。跑 `l3build unpack` 后 `.def` 只有 1129 字节——版权头有，数据没有。

原因是 `build.lua` 的 `unpacksuppfiles` 没列 `xpinyin-query.db`，docstrip 在 unpack 目录里找不到它。

我当时记成「这个失败不报错」，审查时被证否：`build/` 干净时 unpack 会以退出码 1 加 `! Cannot find file xpinyin-query.db.` 明确失败。我看到的「静默产出空表」是因为 `build/` 里留着上一次的产物。**这是又一次把自己环境的残留状态当成工具行为**，与前面「用自己的正规化步骤污染判断」是同一类错误。

## What Went Right

**可展开性这条约束是先验证再设计的。** 动手前先测了三件事：纯查表的命令能否用在 `\edef`、`\index` 排序键、`\csname` 里（能）；去声调需要的 `\char_to_nfd:N` 能否嵌在可展开上下文里（不能，实测报 100 个错）。这两个结果直接决定了「预生成」这个方案形状，避免了先写一版运行时计算的实现再推翻。

**expl3 里哪些条件式可展开，是逐个试出来的而不是猜的。** 用独立最小文件试了八九轮，比在完整实现里调试快得多。

但**试的方法有缺陷，得出了两个错误结论**（审查时被证否）：我把 `\str_case:nnF` 和 `\prg_new_conditional` 的 `TF` 形式记成不可展开，实际它们可展开。当初失败的真正原因是我在判据参数里嵌了未展开的函数调用（`\str_case:nnF { \last:n {#1} } {...}`），`\str_case` 拿字面 token 比对，永远匹配不上就走了 `F` 分支。先用 `\exp_args:Nf` 展开判据即可。

这个错误比「不知道」更糟：它写进了 reference 层，会让后来者绕开本来可用的工具。教训是**诊断「某函数不可展开」之前，先排除「我没展开判据」**。

**变异测试做了双向。** 把 `ǚ` 的字母部分从 `v` 写成 `u`（`nv3` 变 `nu3`、字形变 `nǔ`）与让 `official` 表也收 `y`/`w`（两模式合一）各跑一次，都确认变红。第二个变异第一次跑时是绿的——因为我在注入前误用 `cp` 把 dtx 恢复了，变异根本没生效。重新注入后才变红。

## Missing Docs or Signals

- `llmdoc/reference/coding-conventions.md` 没有「哪些 expl3 条件式可展开」这类信息。这次靠逐个试，花了八九轮。至少应记下「要写可展开代码时，`\str_if_in:`／`\str_case:` 一类不可用，改用 `\int_compare:nNnTF` 与 `\cs_if_exist_use:cF`」这条经验。
- `llmdoc/reference/build-and-test.md` 记了 xpinyin 的测试设计，但没有记 `unpacksuppfiles` 与 docstrip `\from{}` 的关系。新增一个数据文件时必须同时改这两处，漏一处会静默产出空表。
- `lessons-learned.md` 里有「测试全绿不构成判别力证据」，但没有「表驱动转换要全量对拍」这一条。#550 的裸组合符例外正是抽样的盲区。
- 手册（`xpinyin.dtx` 的 documentation 段）此前没有说明 `\pinyin` 的 `v`→`ü` 只在 `l`／`n` 之后生效。这个限制决定了两处韵母不能标调，属于对下游可见的行为边界。

## Promotion Candidates

以下五条已在本轮全部落地，括注为去处。


1. ✅ **已落地** → `llmdoc/reference/coding-conventions.md`「写完全可展开的命令时可用的工具（#550）」：记录实测结论——`\str_if_in:nnTF`、`\str_case:nnF`、`\prg_new_conditional:Npnn` 的 `TF` 形式都不可展开；可展开的替代是 `\int_compare:nNnTF`（比较码位）、`\cs_if_exist_use:cF`（表驱动分派）、`\str_range:nnn`、`\clist_map_function:nN`。并记 `\exp_args:Nnc` 用于给 `map_function` 传具名函数，避免在可展开命令里 `\cs_set:Npn`。
2. ✅ **已落地** → `llmdoc/reference/build-and-test.md`「拼音查询命令的回归（`pinyin-query01`，#550）」：新增由 `xpinyin.lua` 生成、经 docstrip `\from{}` 并入 `.def` 的数据文件时，必须同时加进 `build.lua` 的 `unpacksuppfiles`；漏掉时 unpack 不报错，只产出仅含版权头的 `.def`（实测 1129 字节），判据是核对生成文件的大小。
3. ✅ **已落地** → `lessons-learned.md`「表驱动的字符转换要用全量数据逐条比对，抽样只能证明主路径」：抽样只能证明主路径。#550 的实例是「呣」的 `m̀`——Unicode 没有 `m` 加钝音符的预组合形式，所以它以裸组合符出现，按整字符查的对照表漏掉了它，而抽样六个字全对。
4. ✅ **已落地** → `lessons-learned.md`「确认数据的实际形式时，不要经过自己加的正规化步骤」（另补两条：变异实验后先确认变异生效、写可展开命令前先实测候选函数）：#550 调研阶段每次统计都调了 Python 的 `normalize('NFD')`，于是把「正规化之后的样子」当成了数据原本的样子，据此写的 Lua 代码是空操作。判据是直接看码位数或原始字节。
5. ✅ **已落地** → `xpinyin/MAINTAINING.md`「`\pinyin` 的 `v` 到 `ü` 只在 `l`、`n` 之后生效」：`\@@_replace_v:n` 只在前一个字母是 `l`／`n` 时把 `v` 当作 `ü`（因为 `ju`／`qu`／`xu` 无歧义）。因此以 `v` 开头的片段标不出 `ü`，`\pinyin{v3}` 排出来是 `ǔ`。查询命令的两处韵母不标调正是这个原因。

## 另一处收获：读约定文档改出了两个不合规写法

本轮按 llmdoc-update 的要求先读 `coding-conventions.md`，读出两处自己刚写的代码不合仓库约定：

- `.choices:nn` 的分支代码里用了 `\l_keys_choice_tl`，而约定明确要求优先用 `#1`（`ctex` 的 `space` 选项踩过坑：延迟展开时该变量已不持有当时的值）。已改。
- 用了 `\clist_put_right:Nx`，而仓库自 #679 起全面用 e-type 代替 x-type。已改为 `:Ne`，相关注释里的「x 类展开」一并改为「e 类展开」。

两处都不影响当时的测试结果，属于纯约定问题——**靠跑测试发现不了，只能靠读约定**。这也说明 llmdoc 的价值不只在记录，先读一遍能拦住这类问题。

## 独立审计发现的（第一轮盲审：2 阻塞／4 重要／5 小）

审查者独立复算了全部数值断言（44360、6268、3869、238、29 项、1.07 MB、「呣」的例外）并复现了两个变异实验，都吻合。但发现了六类我没查到的问题，其中三类是**我把自己的错误当成了工具或库的性质**：

### 1. 最严重的一条：`\index` 不展开参数，手册的核心用法不生效

整个预生成方案是为了「能写进 `\index` 排序键」，而我从没端到端验证过这件事。`\index` 先 `\@sanitize` 再原样写进 `.idx`，所以 `\index{\xpinyinvalue{汉}@汉字}` 存的是命令本身。我早期确实测过「`\index` 里放查询命令不报错」，但把「不报错」当成了「生效」——没去看 `.idx` 的字节，也没跑 makeindex 看排序。

雪上加霜的是同一场景下报错也不出现（`\@@_query_missing:n` 是 `protected` 的，命令没展开就不触发），于是缺少 `query` 选项的文档会零错误编译并静默产出错误索引——正是决策里说要避免的失败方式。

教训：**验证一个用途，要验证它的产物，而不是「没报错」**。这与 #997 那次「盒子尺寸恒真」是同一类错误的不同表现。

### 2. 死代码，而且教训注释挂在死代码上

当时的 `\@@_query_select:nn`（已在同一轮删除）其 scheme 分派不可达；`affix` 一对、`join`、四个 `item_*` 共 6 个函数从未被调用（`item_*` 是我中途放弃的 `\clist_map_function` 方案的残留）。我在实现时反复重构，每次都留下了上一版的函数。

更值得记的是：「声母永远不带声调」这条教训只作为注释存在于死掉的 `affix_aux` 上。按那条注释去改代码的人会发现改了没反应、测试也不红。修复时把该注释移到了活代码 `\@@_query_part:nn` 的 shengmu 支上。

### 3. 把自己的展开错误记成了库函数的限制

我在 reference 层写「`\str_case:nnF` 与 `\prg_new_conditional` 的 `TF` 形式不可展开」，审查实测证否：它们可展开，只有 `protected` 变体不可。当初失败的真正原因是我在判据参数里嵌了未展开的调用（`\str_case:nnF { \last:n {#1} } {...}`），先 `\exp_args:Nf` 展开判据就好了。

这个错误比不知道更糟——它写进了 reference，会让后来者绕开本来可用的工具。

### 4. 又一次把环境残留当成工具行为

「漏掉 `unpacksuppfiles` 时 unpack 不报错」是错的：`build/` 干净时它以退出码 1 加 `! Cannot find file` 明确失败。我看到的「静默产出 1129 字节」是因为 `build/` 里留着上一次的产物。而我还在文档里写了「不要只看退出码」这条反向指导。

与「用自己的正规化步骤污染判断」同类：**都是把自己环境或工具链的状态当成了被观察对象的性质**。

### 5. 恒真断言（第三次踩同一类坑）

测试第 8 项写 `\index{...}` 后跟 `\TYPE{index: no error}`。`\TYPE` 无条件执行，这行无论实现对不对都会打出来，对它声称覆盖的场景零判别力，反而把缺陷冻结成了预期基线。已改为断言 `\edef` 之后的字面值与 `\meaning`，并用「把 `tone_apply` 改成 `protected`」这个变异验证会变红。

### 6. LuaTeX 表述错误

手册与报错文案都写「XeTeX 与 LuaTeX」，但 xpinyin 的包级门禁在 LuaTeX 下直接 `\msg_critical` 中止。我把包级限制与本功能限制混为一谈，还会把 pdfTeX 用户导向一个同样不可行的引擎。引擎判据也顺手从「不是 pdfTeX」改为「必须是 XeTeX」。

### 其余

参数校验缺失（多字／空参数漏出底层 TeX 错误，已加 `\tl_count:n` 检查）、一处 `\begin{macrocode}` 不配对把 4 行注释排进了手册（是我删死代码时留下的）、`\begin{macro}` 条目名写成 `:nn` 而实际是 `:n`、两个函数缺条目、`tone` 表里 `none` 与 `v` 两行完全重复。

## 第二轮盲审：同一失效方式在「修好」之后又发作两次

增量盲审（范围 `534f4062..ce514067`）复算并确认了上一轮全部自述为真的部分，但在**我这一轮新写的手册配方上**又发现 2 阻塞 4 重要 5 小。这一点值得单独记：

第一轮的阻塞 1 是「只验证了没报错，没验证产物」。我据此重写了手册配方——**然后又没有端到端验证这个新配方**。结果同一处再犯两次：

1. 配方用 `\@tempa` 作中间变量，正文里 `@` 不是字母，`\edef\@tempa{...}` 定义到的不是 `\@tempa`，排序键多出一个空格（`han @汉字`）。makeindex 按字面比较，会把它与手写的 `han@汉字` 分成两个条目。
2. 我在手册里承诺该配方「能在缺少选项时立刻发现问题」。实测不成立：`\@@_query_missing:n` 用 `\msg_error:nnn`，它是 `protected` 的，在 `\edef` 里既不报错也不展开，于是 `.idx` 里写进 `\__xpinyin_query_missing:n {汉}@汉字`——**第一轮认定为阻塞、并写进决策文档和 lessons-learned 的那个失效方式依然存在**，只是坏键的内容换了。

也就是说，我在「记下这条教训」的同一次提交里又违反了它。修法是改用 `\msg_expandable_error:nnn`（`zhnumber` 在本仓库已有先例）。

其余：`\tl_count:n` 数的是记号而非字符，`{中}`、`\hz` 会通过校验后照旧漏出底层错误（改用 `\str_count:n`）；测试里改动后**再没有任何一处实际调用 `\index`**，`.tlg` 固定的是 `\edef` 的中间产物而缺陷出在 `.idx` 的最终字节上——这正是两个阻塞同时溜过的原因（现已固定交给 `\index` 的实际字节，并保留一格含 `@` 名字的对照）。

审查者还纠了我一处计数口径：当时的 `\@@_query_select:nn` 在基线里是被调用的（`value` 走它），属「内部分派不可达」而非「从未被调用」，与另外 6 个真正零调用的函数并列说成「7 个从未被调用」不准确。该函数已在同一轮删除，此处按当时的代码状态叙述。

另一个实测得来的测试约束：可展开的报错会中断当前 `\edef` 与其后的断言，两个报错场景放同一个 `.lvt` 时只有前一个有效（变异实测：另一个照常全绿）。因此拆成 `pinyin-query02`（参数校验）与 `pinyin-query03`（查不到读音）各占一个文件。

## 第三轮盲审：修法本身删掉了覆盖

增量盲审（`ce514067..6a87195c`）又发现 2 阻塞 3 重要 4 小。最重的一条是**我上一轮的修法把测试覆盖静默删掉了**：把 `tone=mark` 的排版节点基线搬进了 `pinyin-query02.lvt` 里参数校验报错之后的位置，而 `checkopts` 带 `-halt-on-error`，第一处错误即终止编译。那一节从此从未执行，`.tlg` 只剩 12 行止于报错；星号去重与标调两处变异实测都变成全绿。

**根源是我自己写下的一条归因错误的规则。** 我把中断记成「`\msg_expandable_error:nnn` 会中断当前 `\edef` 与其后的断言」，于是以为报错之后放什么都无所谓。实测不加 `-halt-on-error` 时，报错之后的断言全部照常执行——中断来自门禁选项，与该命令语义无关。

更值得记的是：**仓库里本来就有这条正确记录**。`pinyin-tone02.lvt` 的注释写着「`\box_log:N` 抛 `! OK.`，而 checkopts 带 `-halt-on-error`，当场终止编译——其后的用例静默不执行，check 却可能仍报绿」，`build-and-test.md` 也有同源段落，而我在 `pinyin-query01.lvt` 自己的注释里还引用过它。我有正确的规则可用，却另写了一条错的，并据此改动了测试布局。

这已是本任务里第四次同类错误：把自己的观察或推断当成机制本身（NFD 分解形式、`str_case` 不可展开、unpack 不报错、以及这次）。四次的共同点是**没有把「我看到的现象」与「造成现象的原因」分开验证**。
