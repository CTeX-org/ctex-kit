# 反思：#1067 花括号分组使 ulem 装饰内 `\CJKecglue` 收缩量固化，与「改掉无效」两次读反方向

## 任务

Issue #1067：`\CJKunderline{虚室 {hello} 生白}` 里，花括号使该处中西文间距（`\CJKecglue`）
的可收缩量失效。压窄 2pt 时 badness 从 55（oracle）变 1000000，即压不进去，`\hbox to`
一类固定宽度场合会溢出。自然宽度不受影响，段落断行时两种写法都不溢出、视觉一致——这也是
这条限制此前一直没被独立报告的原因（此前只在 `fntef-shrink01.lvt` TEST 9 的注释里记成
「已接受的限制」，未开成 issue）。

## 结论与实现

修好了，不是既有限制。提交 `015e8a86`。

机制：`ulem` 按源码空格切词，实测两种写法切出的词相同（`WORD=[\prg_do_nothing: hello]`
vs `WORD=[\prg_do_nothing: {hello}]`），花括号不影响切分点。花括号是在词内容交给
`\UL@start` **之后**、在片段盒**内部**才展开成分组的，于是 xeCJK 的边界检测在盒内、且在
用户分组内触发；`\@@_ulem_glue:n`（`xeCJK.dtx:14811`）的 group tag 守卫比对保存的
`\l_@@_group_tag_tl`（值 `T1L4`）与当前的 `\c_@@_group_tag_tl`（值 `T1L5`，花括号让
`\currentgrouplevel` 加深）不相等，走 else 分支：该分支原先是裸 `\skip_horizontal:n`，
间距连自然宽度带收缩量一起固化在定宽片段盒内，外层取不到。

不能改成「照样搬运」（强制走 `\UL@stop` … `\UL@start`）：实测搬出来的 glue 落进
`\cleaders` 内部，仍在盒内——`ulem` 开盒时开了两层，用户花括号插在中间，在用户分组内
`\UL@stop` 关不掉正确层级，`\UL@start` 重开的盒子又把它包了回去；而且绕过守卫会让分组内
字体设置丢失（`fntef-font01` 失败，字体从 `FandolKai` 退回 `FandolSong`）。

修法（`\@@_ulem_defer_glue:n` / `\@@_ulem_flush_pending_shrink:`，`xeCJK.dtx:14899` 起）：
把一处间距拆成两半输出。盒内放不可伸缩的 `kern` 占住自然宽度（排版位置与盒宽都不变）；
伸缩量记进全局 `\g_@@_ulem_pending_shrink_skip`，到 `\@@_ulem_loop:nw` 的词尾搬运处
（`xeCJK.dtx:13865`，已在片段盒外、用户分组外）再补一个零宽带伸缩的 glue。守卫本身
**未改动**。自然宽度为零的间距必须短路直接输出（`\CJKglue` 是 `0pt plus 0.96`，只有
伸长没有收缩，换成 `kern` 会连伸长量丢掉；漏掉短路时 `fntef-font01` 盒宽从 `40.0pt`
变 `39.00002pt`）。记账是全局量，`\@@_ulem_end:`（`xeCJK.dtx:13852`）在装饰结束时清零，
防止串到下一次装饰。

效果（压窄 2pt 的 badness，修复前 → 后）：`虚室 {hello} 生白`、
`虚室 \textbf{hello} 生白`、`虚室 {{hello}} 生白` 三者都从 1000000 变成有限值；
oracle 与无编组形态不变。

**两组数值不要混用**：本文与 PR 里的 `55` 来自 MWE 的 `\documentclass[11pt]`（见
`gh-assets` 的 `issues/1067/issue1067-measure.tex`），而 TEST 11 基线里的 `73` 来自
`fntef-shrink01.lvt` 的 `\documentclass{article}`（默认 10pt）。同一现象、不同字号，
badness 反映的是收缩比例，随字号与压窄量变化。判据是「有限值 vs 1000000」这个定性区别，
不是某个具体数字——引用时要连字号一起说，否则下一个人会以为其中一个读数是错的。

TEST 11 的四个变异均实测有判别力：去掉记账、去掉 flush 调用、去掉零宽短路，以及把 flush
移回 `\UL@leaders` 之后（后者由独立盲审发现，见下文「独立盲审发现的回归」一节）。

`\CJKunderline{虚室 {文字} 生白}`（纯汉字）**不在**本次范围：它的 oracle 本身就是
1000000（汉字之间只有 `\CJKglue`，没有可收缩间距），与编组、装饰命令都无关——这一点我
在探索阶段一度误列为「受影响」，实测 oracle 后否证。

## 核心教训：同一个「改掉它无效」的观察，被我两次读反方向

这是本次最值得记的部分，因为它是同一枚证据被两次误用、且误用方向恰好相反的连续实例。

**第一次误读（在本次修复之前，即遗留在 `fntef-shrink01.lvt` TEST 9 注释与
`llmdoc/architecture/xecjk-architecture.md` 里的旧记载）**：只观察到「花括号触发守卫
MISMATCH 分支」，就写成「守卫拒绝搬运，这是刻意设计」，隐含的意思是「这就是最终成因，
无法再深入」。这句话本身不算错（守卫确实是直接原因），但它止步于此，没有解释「为什么
不能简单绕过」，读者会以为改掉守卫即可修好。

**第二次误读（本次任务早期，见 `tmp/i1067/findings.md`）**：做了变异测试——把两份守卫
（`\@@_ulem_glue:n` 与 `\@@_boundary_use_ulem_glue:n`）都改成无条件搬运，braced 形态的
badness **仍是 1000000，读数一个字都没变**。据此我写下「守卫与本问题无关，真正根因是
编组改变了 ulem 的切词结果」——**这一次连方向都反了**：不是「守卫不影响结果」，而是
「守卫的判断是对的，绕过它也解决不了，因为问题出在更早、绕过守卫这个动作已经来不及」。

推翻这个第二版归因用的是节点级证据（`tmp/i1067/correct-mechanism.md`）：`\showbox`
比对显示两种写法切出的片段盒**数量相同**（都 5 个），只有第三个盒宽不同（20.56pt vs
23.89pt，差 3.33pt，恰为 `\CJKecglue` 自然宽度），说明切分点没有变化，「编组改变了切词」
是假的。而「强制搬运后 glue 落进 `\cleaders` 内部仍在盒内」这条证据本身没有变过——它从
第一次实验起就在那里，只是我先把它读成「守卫非根因的证明」，没有意识到它同时也说明
「守卫是根因，只是绕过它的动作本身在这个位置做不到」。

**这两次误读是一次跳步推理的两种表现**：从「改掉某个环节，现象没变」直接跳到「这个环节
不是原因」。这两件事完全可以同时成立——「A 是直接原因」与「绕开 A 这个动作本身失败」
是独立的两个命题，前者问的是「代码走到哪个分支决定了结果」，后者问的是「换一种做法能不能
成功」。本次的真实情况是两者都成立：group tag 守卫确实是让间距落进 else 分支的直接原因；
但把 else 分支改成「无条件搬运」这个具体修法不成立，因为搬运动作发生的时机已经晚了（花括号
分组已经把 glue 关进了盒子结构里）。

这与 `llmdoc/memory/lessons-learned.md` 里「现象、联系、穷尽性、成因是四个独立命题」
（Source：[[1046-1047-meta-anchor-font-context]]）同源，但是它在「成因」这一层的**镜面
发作**：#1046/#1047 那次是把「A 缺了会坏、B 缺了也会坏」（可达）误当成因（「按某条件在
A、B 间分派」或「只有 A 和 B」）；这次反过来，是把「改掉 A 之后现象仍在」（修法无效）
误当成「A 不是成因」的证明。前者是从「可达」过度推出机制，后者是从「修法失败」过度推出
「非成因」——两次都省掉了本该单独验证的一步，本次省掉的是「搬运动作为什么会失败」这一层
（真实原因是分组结构，不是守卫本身）。

## 教训的直接后果：过早判定不可修复、已开又关掉一个 PR

第二版归因（「与守卫无关，根因是切词失效」）不仅是错的机制陈述，还直接改变了处置结论。
按这个假根因，`tmp/i1067/correct-mechanism.md` 列出的「已排除的修法方向」全部围绕
「切词」或「守卫」设计（无条件走 ulem 通道、记账后续兑现、搬运后恢复字体、在分组前输出
glue），四条都受阻，于是判定「只能文档化，不改实现」，据此开出并推进了 PR #1070
（`docs(xeCJK): 说明花括号使装饰正文内间距收缩量失效的限制`），最终该 PR 被关闭
（见 `tmp/pr1067/close.log`）。

真正的修法——盒内 kern 占位（保持自然宽度不变）加词尾记账补伸缩（把伸缩量搬到分组外、
盒外再兑现）——在正确根因下并不难找，且守卫本身完全不用动。但只有先把「根因是切词」
这个假结论推翻、确认「根因是花括号让 glue 出现在了错误的一侧，而非切分点丢失」之后，
才有机会看到这条路径：既然自然宽度不需要搬运（它留在盒内不影响外观），只搬运伸缩量，
就不需要经过 `\UL@stop`／`\UL@start` 那个在用户分组内不安全的动作。

**教训**：根因判断一旦更正，基于旧根因得出的「不可行」结论要整体作废重新评估，不能只
挑其中被直接指出错误的那一句改掉、其余「已排除方向」的清单原样保留。本次任务里这一步
是在同一个会话内做到的（第三次修正 `tmp/i1067/correct-mechanism.md` 后立刻重新设计
修法），但更早已经开过一次以旧根因为前提的 PR 并被关闭——说明「重新评估」这一步不能
只做一次，每次结论变化都要重新过一遍处置决策，而不是假设「反正现在文档化了，以后有空
再看」。

## 贴图与文字说法不匹配：视觉证据的验证责任在贴图者

关闭的 PR #1070 里贴过一张对比图，文字写「有编组：溢出框外」。用户指出实测该处溢出量
只有 0.676pt，12pt 字号在 170dpi 下不到 2 像素，图上根本看不出来。同一张图第四行还有
`\CJKunderdot` 之后的 `\ ` 被吃掉、框与文字之间缺间距的问题，也未在图注中说明。

（本次任务用的最终对比图改用 12pt 字号、正文压进 78pt 这组几何，四行读数分别是
plain/color/underdot 的 badness 43 与 braced 的 1000000——用 badness 的量级差异而不是
像素级的溢出量差异来选取参数，读者不需要在图上分辨亚像素级别的边界。)

**教训**：贴图前要自己核对图上是否真能看到文字所声称的现象，不能假设「badness 不同就
一定看得出来」。当两种情形的物理差异小到亚像素级别时，应当换成数值呈现（表格、badness
读数）而不是硬贴一张实际看不出差别的图；若确实要用视觉证据，需要先选取能把差异放大到
可见范围的参数（本次是换用更大字号、更紧的压窄目标）。这条与
`llmdoc/memory/lessons-learned.md` 里「弹性 glue 的三项参数与实际断行」同属一类，都是
「选错了观察量/呈现方式会让证据本身失去判别力」，但这次是视觉呈现层面的实例。

## 具体的坑

### 同一函数有两份定义，改错位置会得到假的「变异全绿」

`\@@_use_ecglue_skip:` 在主体用 `\cs_new_protected:Npn` 定义一次（`xeCJK.dtx:3913`
附近，普通 `\skip_horizontal:N`），在 `xeCJKfntef` 部分用 `\cs_gset_protected:Npn`
覆盖一次（`xeCJK.dtx:14854` 附近，加了装饰 stream 守卫）。装饰状态下生效的是后一份。

本次任务与 1067-b 盲审协调阶段都各自踩到过这个坑：第一次改错位置，得到「变异全绿」的
假结果，差点据此得出「这处代码不影响结果」的错误结论；协调者自查（`.code-review/runs/
1067-b/coordinator-self-check.md`）里也专门记了这一条并写进后续审查员的提示词。

**教训**：做变异实验前，必须先确认变异真的生效——插一句 `\iow_term:n` 打点，或者
`grep` 解包产物确认改动确实出现在最终生效的那份定义里。这与 `llmdoc/memory/reflections/
931-biblatex-pagetracker-let-shadow.md`（补丁挂在 `\let` 源函数不生效，`\let` 目标才是
真正的绑定点）是同一类坑的另一种表现：符号名相同、绑定形态或定义顺序不同，导致改的不是
生效的那一份。

### 自然宽度为零的间距不能走 kern 占位

`\CJKglue` 是 `0pt plus 0.96`，只有伸长量、没有收缩量。如果不区分自然宽度是否为零、
统一把间距拆成「kern 占自然宽度 + 记账伸缩量」，会把伸长量也一起丢掉——`kern` 没有伸缩
属性，伸长量记进 `\g_@@_ulem_pending_shrink_skip` 后要等到词尾才兑现，中途这段自然宽度
为零的间距会在盒内变成纯 `kern`，实测 `fntef-font01` 的盒宽从 `40.0pt` 变成
`39.00002pt`。TEST 11 的 `cjkglue-braced-width` 断言专门盯这一点。

### regression-test 环境下寄存器编号与 catcode 限制

`fntef-shrink01.lvt` 用高编号寄存器（`\setbox20`–`\setbox28`、`\dimen20` 等）避开
`TEST` 框架和先前用例占用的低编号寄存器。这与 `llmdoc/memory/lessons-learned.md` 里
「测量类用例一律用具名 box 寄存器」是同一条规则的具体落实，本次未新增规则，只是再次
验证了它的必要性。

**这条改进已在本轮验证有效。** 第三轮（`.code-review/runs/1067-c`）改成：要求审查员在动手

形态。

### 盲审抓到了协调者漏掉的回归

更要紧的是：这一轮盲审**真的抓到了一个 blocking**，而且是协调者自查完全漏掉的一类。

第一版修法把 `\@@_ulem_flush_pending_shrink:` 放在 `\UL@stop \UL@leaders` **之后**。
编组出现在装饰参数**结尾**时，补出的 glue 会把 `\UL@leaders` 末尾那个 `-\UL@pixel`
（段间重叠补偿，实测 `-0.99998pt`）推到更后面，使它失去正向配对，装饰盒因此比 oracle 窄
1pt：`\CJKunderline{中{x}}` 得 `17.61002pt` 而 `\hbox{中{x}}` 是 `18.61pt`；
`\CJKunderline{虚室 \textbf{word}}` 同样少 1pt。修正是把 flush 移到 `\UL@leaders`
**之前**，让 glue 落在两段装饰之间。

为什么协调者漏了：我的全部验证都围绕「编组在中间」（`虚室 {hello} 生白`）这一种位置，
TEST 11 最初的五条断言也都是这个形态。而这个回归只在「编组在结尾」时出现——**同一个缺陷的
不同位置是不同的用例**，修好了中间不等于修好了结尾。审查员是自己另设了「正文以编组开头或
结尾」这一组 MWE 才撞上的，并且它给的证据链完整到可以直接照做：fixed／base／oracle 三方
宽度对比、`\showbox` 定位到多出的 `\glue -0.99998`、以及「删掉 flush 调用即恢复」的定位实验。

盲审的第二个 finding（minor）也被采纳了：记账是全局量，而清零原先只放在 `\@@_ulem_end:`，
但代码注释自承行内公式里的装饰命令经 `\UL@onmath`／`\UL@onin` 结束、不走那里。审查员自己
构造了公式路径的 MWE 实测，**没有**观察到可见串味（四条路径残留都是 `0pt`，因为记账在词尾
都已兑现），如实写成「暂未见可见影响，但结构上不够稳」并标为非必须。我采纳了它：在
`\@@_ulem_stream_begin:` 进入装饰时再清一次，作为防御性隔断。这是一条好 finding 的样子——
把「理论风险」与「实测未复现」分开陈述，而不是硬报成缺陷或干脆不提。

教训有两层。一是**位置也是维度**：验证一个与「相邻关系」有关的修法时，要把被修的构造分别
放在开头、中间、结尾各测一遍，不能只测最自然的那一种。二是**这类回归靠作者自查很难发现**，
因为自查的用例集通常就是当初复现缺陷用的那一组——盲审的价值恰在于它不共享这个起点。

## bot 审查抓到的第三类问题：取 glue 分量会丢掉阶数

`agentic-pr-review` 在 PR #1071 上报了一个 blocking，指出 `\tex_gluestretch:D` 与
`\tex_glueshrink:D` **只返回数值**，阶数在 `\gluestretchorder`／`\glueshrinkorder` 里；分开取
再用 `plus`／`minus` 重拼，会把 `1fil` 静默降成普通阶。实测：`3.33pt plus 1fil minus 1.11pt`
用「整个 skip 减去自然宽度」得 `0.0pt plus 1.0fil minus 1.11pt`（阶数保留），而
`\tex_gluestretch:D` 只给出 `1.0pt`。

已改为 `\skip_eval:n { #1 - \dim_eval:n {#1} }`。这条值得记成通用规则：**在 TeX 里取 glue 的
弹性部分，用整个 skip 减去自然宽度，不要分别取 stretch 与 shrink 再拼**——后者丢阶，而且丢得
无声无息。

两点补充，都关系到怎么对待这类 finding：

**一、诊断正确但在当前路径不可达。** 我在 `\@@_ulem_defer_glue:n` 里插桩确认，装饰状态下传进
来的自然宽度已经是零（`DEFER in=[0.0pt] order=0`），会走零宽短路，根本走不到取弹性部分那一步；
即使显式设 `\xeCJKsetup{CJKecglue={3.33pt plus 1fil minus 1.11pt}}`，节点列表里两侧都没有
`fil`——阶数是在更上游的 `\xeCJK_glue_to_skip:nN` 求值时消失的，与本次记账无关。仍然采纳，
因为新写法更短且不依赖这个前提；但在回复与提交信息里如实写明「这是防御性修正，不修实际缺陷」，
而不是含糊地记成「修了一个 bug」。

**二、同一条 finding 里的第二半经实测不成立。** bot 还说零自然宽度短路会让 `0pt minus 1pt`
这类 glue 的收缩量继续留在盒内。实测否证：用 `CJKecglue={0pt minus 1pt}` 压窄 0.8pt，
oracle／plain／braced 三者 badness 都是 37，修复前后一致。原因是零自然宽度的间距原地放置时
收缩量本来就能被外层用到——它不占宽度，无须搬运。反过来这个短路是必需的（`\CJKglue` 是
`0pt plus 0.96`，换成 `kern` 会连伸长量一起丢，`fntef-font01` 盒宽会从 `40.0pt` 变
`39.00002pt`）。

也就是说：**一条 finding 的两半可以一半成立一半不成立，要分别验证**，不能因为前半段说对了就
整条照改，也不能因为后半段不成立就把整条驳回。

顺带又踩了一次已知的坑：补写这段说明时把 `\texttt{#1}` 的参数记号漏了转义，`l3doc` 报
`Illegal parameter number in definition of \reserved@b`，手册构建失败。`coding-conventions.md`
里已有「`\changes` 正文中的 `#1` 等参数签名要转义」这条，范围应当理解为**所有 `.dtx` 文档注释**，
不只是 `\changes`。

## Promotion Candidates

- **「改掉它无效」不能推出「它不是原因」。** 这条应作为 `lessons-learned.md` 里「现象、
  联系、穷尽性、成因是四个独立命题」的镜面补充：排除法要求同时证明「替代解释成立」，
  不能只凭「这个解释对应的修法没奏效」——修法失败可能只说明修法本身受阻于别的结构
  （本次是「用户分组内 `\UL@stop` 关不掉正确层级」），而不是这个解释本身错了。
- **根因判断更正后，基于旧根因的「不可行」结论要整体重新评估，不能只改被指出错误的那句
  话。** 值得单列一条：判定「无法修复、只能文档化」之前，先确认这个判断依据的是当前
  根因还是已被推翻的旧根因；若根因刚刚变化，要重新过一遍此前列出的每一条「已排除方向」，
  而不是假设它们仍然成立。
- **贴图前要自己核对图上是否真能看到文字所声称的现象。** 差异过小（本次 0.676pt、
  170dpi 下不到 2 像素）时应改用数值呈现（表格、badness/宽度读数），或者选取能把差异
  放大到可见范围的参数，而不是硬贴一张实际看不出差别的图。
- **做变异实验前先确认变异真的生效。** 同一控制序列若在代码里有多份定义（`\cs_new_
  protected:Npn` 后又被 `\cs_gset_protected:Npn` 覆盖），改错位置会得到虚假的「变异
  全绿/全变」结果。核实手段是插桩打点或 grep 解包产物。
