# #1119：加载期失败的日志与诊断对照

## 现象与证据边界

PR #1121 首轮 push 测试中，macOS 的 `jamo-cj01` 输出为空，diff 只有原基线被删除的行。该测试的 `\START` 位于导言区之后；这类 diff 无法显示在它之前发生的错误。原运行只上传了 diff，未保留实际错误，不能据此判断是字体、宏包还是其他加载问题，也不能把空输出保存为新基线。

后续只为默认小包测试增加 `--show-log-on-error`，没有修改该测试输入或基线。第二轮三平台测试通过，但失败未复现不等于根因已查明；这项改动改善的是后续失败时的诊断信息，不是对 `jamo-cj01` 根因的修复。

## 对照必须使用相同的调用方式

验证日志选项时，第一次探针显式指定单个测试。l3build 在这种调用方式下本来就会显示失败日志，因此两侧都有错误文本，无法证明新增选项有效。

改用与 CI 一致的整目录调用，在 `\START` 前放入受控的 `\errmessage`：不加选项时只有空输出对应的 diff；加上 `--show-log-on-error` 后能看到原始日志中的错误。两侧均以非零退出码结束，确认诊断选项没有把失败变成成功。

## 后续做法

- 诊断空的规范化输出时，读完整原始 `.log` 中的第一个错误，不从 diff 猜根因。
- 验证命令行诊断选项时，保留 CI 的整目录／显式测试名、配置和停止选项等调用条件；先确认对照两侧确实存在可观察差异。
- 同一测试后来通过，只能写成“未复现”，不能补写未经验证的成因。

常用命令及 CI 覆盖范围见 `llmdoc/reference/build-and-test.md` 的「加载期失败的完整日志（#1119）」一节。
