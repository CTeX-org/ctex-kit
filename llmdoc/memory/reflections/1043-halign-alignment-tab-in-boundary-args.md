# #1043 反思：boundary 判断遇到 catcode-4 `&`

任务：修复用户客诉——更新到 xeCJK 3.10.4 后，`\colorbox{...}{$...&...$}` 写在
`eqnarray` 里编译报错。

## 缺陷本身

`\@@_boundary_color_box:nnn` 把**原始**第三参数交给 `\@@_boundary_if_math_head:n`，
后者用 expl3 的 `\tl_if_head_eq_meaning:nNTF` 做语法判断。**（以下是当时的认知，机制描述
已由第 8 条更正为「对齐符在对齐环境里终止宏参数读取」，`\halign` 并没有「置」catcode。）**
该条件式内部要把 token list 包进花括号组再扫描，而 `\halign` 语境（`eqnarray`/`align`/
`tabular`）里用户参数中的 `&` 带 catcode 4，会破坏扫描平衡，报
`! Argument of \__tl_tl_head:w has an extra }.`

回归区间：TeX Live 版 v3.10.3 干净，master v3.10.5 报 26 个错；引入提交是
`c8923052`（#1002 那套 inline-math boundary 代码），与报告者说的「3.10.4 起出问题」吻合。

修复：新增 `\@@_boundary_math_set:n`，在 `_head:n` / `_tail:n` 这一层统一把判断用副本里
catcode-4 的 `&` 换成 `\scan_stop:`。

## 教训

### 1. 坏探针让我把一条假事实写进四份文档（最严重的错误）

我曾断言「`\ExplSyntaxOn` 下 `&` 是 catcode 0（escape），所以直接写 `{ & }` 作模式会
**静默失效**」，并把它写进 dtx 注释、`.lvt` 注释、`coding-conventions.md`、本反思和
`index.md` 两处指针。**这条是假的。** 盲审在快照里实测推翻：

- 在 dtx 所处的环境里 `&` 实际是 **catcode 4**（原因见下面第 1c 条——是 LaTeX 环境默认
  设的，`\ExplSyntaxOn` 不改它；我第一轮误以为是 `\c_code_cctab` 的功劳，那也是错的）。
- 把实现改成我声称会失效的 `\tl_replace_all:Nnn ... { & } ...`，`l3build check`
  **全绿**——若真会静默失效，门禁必须失败（它在真缺陷下确实 EXIT=1）。

根源是**探针坏了而我没自证**。我原来的写法是

```latex
\iow_term:x { ... \int_use:N \char_value_catcode:n { `& } }   % 错
```

拿已知答案一测就露馅：它把 `{`(123) 读成 0（应为 1）、`$`(36) 读成 0（应为 3）、
`a`(97) 读成 `01`（应为 11）。**每个读数都是废的**，包括那个「0」。改用
`\tl_set:Ne ... { \int_eval:n { \char_value_catcode:n {38} } }` 后自证通过
（92→0、123→1、36→3、97→11），`&` 读到 4。

讽刺的是「探针静默先自证有效」正是我自己写进 `lessons-learned.md` 的规则（#1037 那轮），
这次却没执行。**教训升级为：探针给出的任何反直觉读数，先用已知答案验证探针，再据它下结论；
把结论写进规范文档之前尤其如此。**

保留 `\c_@@_alignment_tl` 常量本身没错（不依赖外部 régime 是合理的防御），但**理由必须
改成防御性设计，不能是假前提**。规范文档尤其危险：它会让后来者规避一种其实合法的写法。

### 1c. 更正假事实时又写了一条未验证的假归因（第二轮盲审抓到）

修掉上面那条后，我把理由改成「expl3 的 `\c_code_cctab` 本就把 `&` 设为 alignment」，
写进 dtx／`.lvt`／conventions／architecture 四处。**这条又是假的**，第二轮盲审推翻：

`\c_code_cctab` 只是 catcode 表**常量**，要 `\cctab_select:N` 选中才生效，而
`\ExplSyntaxOn` 不选它（实测它只改 9、32→9、58、95→11、126→10，**不含 38**；
我最初抄的「34、94、124 也在内」是错的，见第 5 条），
本仓库也从不调用 `\cctab_select:N`。实测（`tmp/i1043/mech.tex`）：环境先设
`\catcode`\&=12` 再 `\ExplSyntaxOn`，`&` 仍是 **12**（对照：`:` 确实被设成 11）；
只有显式 `\cctab_select:N \c_code_cctab` 才给 4。

真正的原因是：**LaTeX 环境默认把 `&` 设为 4（`latex.ltx`），而 `\ExplSyntaxOn` 不去动它**。

**但第三轮盲审又纠正了我为这条事实配的风险描述。** 我写「没有任何机制保证 4，它随
**调用方**环境漂移」，这仍是错的：字面模式的类别在 dtx 被 tokenise 的那一刻就冻结了，
加载之后再改 `\catcode` 对字面写法和常量写法**一律无效**（实测两者结果相同）。真正的风险
在**加载期**——若 `\usepackage{xeCJK}` 之前外层已把 `&` 改成 12，字面 `{ & }` 读进来就不是
对齐符，此后永远静默失配；而常量由 `\char_set_catcode_alignment:N` 现场生成，不受影响。
变异检验的判别力也只在加载期出现：`\catcode`\&=12` 放在 `\usepackage` **之前**时，字面版
得到 `a&b`、常量版得到 `a\scan_stop: b`；放在**之后**则两版一致，无判别力。

**教训（比第 1 条更精确）**：第 1 条的错误是「读数是废的」，这一条的错误是
**「读数正确，但我为它编了一个没验证的原因」**——而且连续错了两次（先归因给
`\c_code_cctab`，再把风险错放到调用期），第三轮才收敛。修正一条假陈述时，替换进去的新解释
同样要验证——否则只是换了个错误。归因性陈述（「因为 X 所以 Y」）必须像事实陈述一样
接受变异检验：能不能构造出 X 不成立而 Y 仍成立的场景？我没做这一步，两轮都栽在归因上。

### 2. 反向验证必须针对真正的假设

我确实跑了「缺陷版 check 必须失败」，也确实 EXIT=1，于是自认为验证充分。但那次变异是
**删除整行替换**，它只能证明「替换有用」，**不能证明「模板 catcode 写错会失效」**。
两个假设不同，需要两次不同的变异。**门禁反向验证的变异点必须与被断言的机制一一对应。**

### 3. 占位而非删除，保住位置语义

先试过直接删掉 `&`。语法判断能过，但 `&$x$` 的首项从 `&` 变成 `$`，被误判成
「首项是公式」。换成 `\scan_stop:` 占位后，实测五种位置（中间／开头／结尾／多个／
嵌套组）的 head/tail 判定都正确。**清理输入以适配下游解析器时，删除会改变位置关系，
替换成惰性 token 才是等价变换。**

### 4. 报告者的两个症状只有一个是真缺陷

客诉说「数学式和 `\paragraph` 标题都出不来」。实测标题症状**无法独立复现**（单独测、
用他的完整导言区测都正常），修掉数学式问题后标题自动恢复——它是第一个症状那串报错
导致后续排版全乱的次生结果。**多症状客诉要逐一验证复现，不要假设它们是并列的独立缺陷；
否则会为不存在的第二个缺陷设计修复。**

### 5. 不要凭「没搜到」断定变体不存在

我曾写下「expl3 不原生提供 `\tl_replace_all:NVn`，需自行 `\cs_generate_variant`」，据此在
dtx 里加了一行声明。实测 `\cs_if_exist:NTF \tl_replace_all:NVn` 为**真**——它是原生的
（`expl3-code.tex:3963` 的 `{ NnV , Nne , NV , ... }` 组加尾部 `n` 补齐），那行声明纯属冗余，
已删除。我当时只 grep 了字面串 `tl_replace_all:NVn`，没搜到就下了结论，而 expl3 的变体是
**按组生成**的，字面 grep 必然搜不到。**判定某函数是否存在，要用 `\cs_if_exist:NTF` 在
引擎里问，而不是 grep 源码。**（对照组 `\tl_replace_all:NnVn` 确实 MISSING，说明这个探针
本身有判别力。）

### 6. 门禁的判别力边界要写下来

盲审顺手测出：把替换值从 `\scan_stop:` 改成 `{ }`（删除）或 `{ $ }`，本文件的测试**仍然
全绿**。也就是说这个门禁固定的是「不报错」，并**没有**固定占位的位置语义（教训 2 那条理由）。
这不是缺陷，但必须在测试注释里写明，否则后人会误以为占位语义有门禁保护。已补进 `.lvt`。

### 7. 门禁「三项覆盖」实为两项空转（终审抓到）

我把三种语境写成同一文件的三个 `\TEST`，注释还写「任一语境失守都能暴露」。终审实测推翻：
xeCJK 的 `checkopts` 带 `-halt-on-error`，缺陷态下 TEST 1 一报错就中止，
**TEST 2／TEST 3 在日志里出现 0 次**——它们从不参与判别，是看起来正规实际空转的校验。

更难堪的是：这条约束是本仓库 #1038 亲自踩过并写进 `build-and-test.md` 的
（「每个能独立触发该缺陷的用例都要有自己的文件」），而我在同一轮任务里\emph{读过}那份文档
（还据它改了测试计数），却没把它应用到自己新写的测试上。已拆成
`halign-amp-boundary01/02/03.lvt`，三个文件逐个实测缺陷版 rc 1。

**教训：读到的约束要主动套到自己刚写的产物上。** 「我知道这条规则」和「我检查过自己是否
违反它」是两件事；后者需要一个显式动作，不会因为前者自动发生。

### 8. 「\halign 把 & 置为 catcode 4」——第四条错误归因（第二次终审抓到）

dtx、架构文档、`.lvt` 三处都写「`\halign` 内 TeX 把 `&` 置为 catcode 4」，并据此说这是
「expl3 条件式对 catcode-4 记号的固有限制」。两句都不对：

- `&` 在 LaTeX 下**默认**就是 catcode 4（`latex.ltx`），导言区、普通段落里都是 4，
  `\halign` 并没有「置」它。
- 报错的真正条件是**扫描发生在对齐环境内**：实测同一个含顶层 catcode-4 `&` 的 token list，
  在普通段落里走 `\tl_if_head_eq_meaning:nNTF` **0 错误**，在 `tabular` 内才报 `extra }`。
  机制是对齐符在对齐环境里会终止 TeX 正在读取的宏参数，不是「catcode-4 记号本身破坏
  括号组扫描」。按错误说法会推出「任何 catcode-4 记号传进 expl3 条件式都不安全」的错误规则。

最刺眼的是：**同一轮里 `coding-conventions.md` 已经写对了**（「LaTeX 环境默认设 4」），
而 dtx 与 `.lvt` 还留着相反的说法。同一事实在三份文档里给出矛盾描述，说明我修文档时是
「哪里被点名改哪里」，没有做跨文件的一致性核对。

**教训：更正一条事实后，要 grep 全仓库把同一事实的所有表述拉齐**，否则会留下自相矛盾的
文档——后人按哪一份都可能是错的。这与第 7 条（读到的约束要套到自己的产物上）是同一类
「局部修正、全局失配」。

七轮独立审查共报 29 个 finding，逐轮分项（与 `.code-review/ledger-1043-final.md` 一致）：

|---|---|---|---|

| 增量 2 | 1 | 2 | 2 |
| 增量 3 | 1 | 2 | 2 |
| 协调者自查 | 1（等效） | 0 | 0 |
| 终审 1 | 0 | 2 | 3 |
| 终审 2 | 0 | 2 | 3 |
| 终审 3 | 0 | 0 | 3 |
| 合计 | 4 | 10 | 15 |

其中 28 个由盲审发现、仅 1 个由我自己逐句自查抓到。第七轮那 3 条 minor 全是
「计数与跨文件表述不一致」——连**修正计数**这件事本身都又错了一轮，见第 8 条。四个 blocking 级问题是**同一失效模式的连续发作**，全落在同一句话的归因上：

1. 第一轮：坏探针给出废读数（`&`=0），我据此写了假事实。
2. 第二轮：读数对了（`&`=4），但我为它编了个假原因（`\c_code_cctab`），又写进四份文档。
3. 第三轮：原因对了，但我把「不满足时的后果」错放到调用期（实际在加载期），再写进四份文档。
4. 第二次终审：又发现「`\halign` 把 `&` 置为 4」这条归因也是假的（catcode 4 是 LaTeX 默认，
   对齐环境只决定扫描在哪里出错），且它与我自己刚写对的 `coding-conventions.md` 互相矛盾。

共同点是：**我验证了「代码改完之后行为对了」，却没验证「我给出的解释是否为真」。**
修复正确 ≠ 解释正确，而写进规范文档、会被后人当规则用的，恰恰是解释。

四个 blocking 级问题全部落在**同一句话的归因**上，这本身是最值得记的模式：
`&` 是 catcode 4（事实，第一轮定的）→ 为什么是 4（第二轮错，归因给 `\c_code_cctab`）→
不是 4 时会怎样（第三轮错，把风险放在调用期）→ 谁把它设成 4（终审 2 错，说是 `\halign` 设的，
实际是 LaTeX 默认；且「对齐环境内才出错」这一层也是那时才补上的）。**事实、原因、后果是三个独立命题，
各自都要单独验证；前一个对了不代表后一个对。**

**协调者自查那一轮我改了做法：不再等盲审，自己把那段注释里每一条断言逐个实测。**
立刻又抓到一条前三轮增量盲审都没查的：我写「`\ExplSyntaxOn` 只动 9、32、34、58、94、95、124、126」，
实测它只改 9、32（→9）、58、95（→11）、126（→10），**34、94、124 前后不变**。
这条是从 expl3 源码附近「看起来像」的列表抄来的，从未验证。教训：**同一段文字里，
被审查者点名的那几句会被反复打磨，没被点名的句子反而成为最后的错误藏身处**——
收工前应当把整段逐句过一遍，而不是只改 finding 指到的地方。

对应的行为改变：凡是要写进 `reference/` 或注释里的**因果陈述**，都要能回答
「构造 X 不成立的场景，Y 还成立吗？」——第二轮的 `\cctab_select:N` 实验、第三轮的
「`\catcode` 改在 `\usepackage` 之前 vs 之后」实验，都是这种检验。对 TeX 代码尤其要问一句：
**这个量是在「读取时」定的还是「执行时」定的？** 我第三轮就是没分清这两个时刻。
另外，本次两条 important 也都是同一类：我把「也报错」具体化成 `Misplaced alignment tab`、
把两个不可比的错误计数并列成「50／52 → 0」，都是**没实测就把数字和名字写具体**。
宁可写「非 0 → 0」这种可复现的弱断言，也不要写一个精确但错误的数字。
