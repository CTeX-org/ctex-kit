# xeCJK `.dtx` 文档边界整理反思

本轮候选提交没有改变 xeCJK 的运行时行为，而是集中修复 `xeCJK.dtx` 的文档源码边界：
为此前裸露在实现说明之间的代码补齐 `macrocode`，统一实现代码的换行，修正 shortvrb、
示例环境和 implementation 环境的位置，并消除手册版面溢出。

## 可复用经验

`.dtx` 同时是程序源文件和排版源文件，因此“代码仍可由 docstrip 抽取”不等于“文档源码
结构正确”。实现代码漏掉 `macrocode` 时，生成的包可能仍然工作，问题却会在手册构建中以
错误排版或晚得多的解析错误出现。检查这类改动时，要同时查看 docstrip 产物和完整文档构建，
不能用运行时测试代替后者。

`support/ctxdoc.cls` 自行构造 `%    \end{macrocode}` 的逐行终止标记，所以标记前的四个空格
属于解析合同，不只是视觉对齐。一次多写空格就使终止行无法匹配，最终表现为与实际位置相距
很远的 quark 错误。遇到这类错误时，应先检查最近的 verbatim 类环境起止标记是否逐字匹配，
不要从末尾错误位置反推业务代码。

shortvrb 也有相同的“局部写法、远端失败”特征：`\changes` 会继续经过索引和文档排版链，
参数记号或过长内容放进 `|...|` 后，可能分别触发解析失败和不可断行。处理方式不是机械替换
所有竖线，而是按内容选择 `\tn`、`\cs`、`\texttt` 或改写句子，并同时检查手册版面。
