# 决策：接受 `X{ }\cmd Y` 相对修复前少一枚空格（#1103）

## 背景

#1103 修复“没有可见输出的已注册命令两侧都有源码空格时多一枚空格”：oracle 是删去命令后的直接输入，两侧的空格相邻、合并为一个记号，所以只应保留一枚空格（机制见 [[../../architecture/xecjk-empty-output-space]]）。

修复靠命令之前的节点列表判断入口有没有源码空格：capture 入口取下了一枚真实的词间 glue（`space_glue` 字段为真），就在命令结束后删去紧跟的源码空格。

本地审查第二轮发现，空格写在花括号里、紧贴命令的写法 `X{ }\cmd Y` 相对修复前是回退：

| 写法 | 修复前 `e641743e` | 现在 | 直接输入（删去命令） |
|---|---|---|---|
| `中{ }\mbox{} 文` | 26.66pt | 23.33pt | 26.66pt（`中{ } 文`） |
| `A{ }\mbox{} B` | 21.24pt | 17.91pt | 21.24pt（`A{ } B`） |

审查者第二轮的外部矩阵在每种间距设置下各有 126 项属于这一类（9 个命令 × 14 种右侧，`01` 写法）。

## 为什么无法区分

`X{ }\cmd` 与 `X{} \cmd`、`X\ \cmd`、`X\space\cmd` 在命令之前留下的节点列表完全相同（左侧是汉字时，列表末尾都是 `CJK` marker 加一枚词间 glue）。capture 入口只能看到这个列表，看不到空格当初是在花括号里还是花括号外，所以四种写法只能按同一规则处理。

可这四种写法的直接输入结果并不相同：

- `X{} \cmd Y`、`X\ \cmd Y`、`X\space\cmd Y`：删去命令后只剩一处空格（`X{}  Y` 的两个空格合为一个记号；`X\ ` 与 `X\space` 之后的源码空格在读入时被跳过），应只保留一枚空格。修复前多一枚空格，现在正确（`中{} \mbox{} 文` 修复前 26.66pt，现在与直接输入都是 23.33pt；`中\space\mbox{} 文` 修复前 26.66pt，现在与直接输入都是 20.0pt）。
- `X{ }\cmd Y`：删去命令后，花括号里的空格与命令之后的空格不相邻，两枚都保留。修复前恰好正确，现在少一枚。

要让 `X{ }\cmd Y` 恢复修复前的结果，就得让另外三种写法回到修复前多一枚空格的结果。

## 决定

维护者决定保留当前修复，接受 `X{ }\cmd Y` 的回退：

- 作为已知限制写入用户手册：`xeCJK/xeCJK.dtx`「CJK 文字与命令交互时的间距」一节新增一段，说明 xeCJK 根据命令之前的节点列表判断源码空格，`前{ }\mbox{} 后` 与 `前{} \mbox{} 后` 按同一方式处理，并附 `\changes` 条目。
- 给出替代写法：确实需要保留空格时，把空格写在命令之后的花括号里（`中{ }\mbox{}{ }文`，26.66pt，与直接输入一致），或改用 `~`（`中~\mbox{} 文`，26.66pt；`~` 在列表末尾留下 penalty，`space_glue` 记为假，命令之后的空格保留）。
- 维护者的理由：四种写法在命令之前的节点列表相同，修好一侧就会让另一侧出错；`X{} \cmd Y`、`X\ \cmd Y`、`X\space\cmd Y` 修复前多一枚空格、现在正确，而 `X{ }\cmd Y`（空格写在花括号里、又紧贴一个没有可见输出的命令）极为罕见。维护者承认这类写法无法完全修正，目前接受这一限制。

## 适用范围：同类的无法区分写法

维护者作决定时说明：类似这样的写法无法完全修正，但极为少见，目前一并接受。本地审查第七轮登记的“空格与空命令之间只有不排出内容的命令或空分组”（`A \sbox0{x}\mbox{} B`、`A {}\mbox{} B`、`A \def\x{}\mbox{} B` 等，`xCJKecglue=false` 时 17.91pt，修复前与直接输入 21.24pt）属于同一原因：命令之前的节点列表与 `A \mbox{} B` 相同。协调者按这句说明把它归入本决定的范围，写入用户手册的同一段落，并在提交 PR 时向维护者报告；维护者若另有决定，以新的决定为准。
